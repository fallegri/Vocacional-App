## High-level view

`escapeHtml()` is applied to every user-visible field in `messages.ts` before HTML interpolation — `displayName`, `studentName`, `methodName`, `dominantCode`, `interpretation`, `verifyUrl`, and `resultsUrl`. The XSS test in `email-messages.test.ts` would catch any regression. The plain-text body deliberately reuses unescaped values, which is correct since plain text is not HTML-parsed.

`x-forwarded-host` is removed from the origin chain in `POST /api/sessions`. Resolution is now `NEXT_PUBLIC_APP_URL → Host (non-localhost) → localhost`, with an inline comment naming the reason. The `Host` branch additionally guards against `localhost:3000` and any hostname starting with `localhost` before constructing an `https://` origin.

The login page unverified-account branch renders "Solicitar nuevo enlace de verificación" and links to `/register?resend=1`. The register page detects `?resend=1` and switches heading, subtext, button label, and success message throughout to reflect a resend flow. The underlying `registerAction` re-issues a token for any unverified account.

The no-password-reset path flagged in v1 remains unimplemented and was explicitly out of scope for this task. The `.env.example` and README document the DB-side recovery procedure. This is the only known gap left open, and it is not blocking.
